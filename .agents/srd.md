System Requirements Document (SRD) — ELITE DIST (Distribution ERP & SFA Platform)1. System Overview & Architectural FlowSystem Name: ELITE DIST — Integrated Distribution Enterprise Resource Planning (ERP) & Sales Force Automation (SFA) System.   Architecture Style: Split Client-Server Architecture (client Frontend Application + server Backend API Server) built on the MERN Stack (MongoDB Atlas, Express.js, React 19 with Vite, and Node.js) with Tailwind CSS and Cloudinary media cloud storage.High-Level System Flow:Client Layer (client/): React Single-Page Application (SPA) styled with Tailwind CSS, featuring a viewport-locked desktop workspace (100dvh), mobile-first responsive card-list views (320px+), and a unified Blue & White (Light Mode) / Blue & Black (Dark Mode) theme engine with smooth transitions and zero purple.   API & Security Layer (server/): Express.js REST API gateway enforcing JWT authentication, Role-Based Access Control (RBAC), granular employee work-part permissions, distributor tenant data isolation, and request payload validation.   Core Business Engines (server/): Dedicated internal engines for 2-Level Invoice & Scheme Calculations, Atomic Batch & Stock Reservations, Pakistan-Style Warehouse/Zone/Floor Movements, Double-Entry Financial Accounting, and Automated Business Alerts.   Cloud Data & Media Layer: MongoDB Atlas serves as the primary transactional cloud database storing all business entities, ledgers, and image URL paths, while Cloudinary handles all image uploads, compression, and CDN delivery.   2. Functional System Specifications2.1. Multi-Distributor Data Isolation & AuthorizationDistributor Scope Isolation: Every distributor maintains completely independent business records, including companies, brands, products, stock batches, warehouses, employees, customers, orders, and accounting ledgers. No distributor can view or modify another distributor's data.   Flexible Distribution Authorization: The system supports configurable authorization rules based on Company agreements, Brand authorization, Product authorization, and Territory agreements, allowing either a single distributor or multiple distributors within the same geographical area.   Environment-Driven Configuration: All system secrets, database connection URIs, Cloudinary credentials, and Super Admin bootstrap credentials reside strictly inside separate .env files (client/.env and server/.env) with zero hardcoded credentials.   2.2. Role-Based Access Control (RBAC) & Work-Part PermissionsPrimary System Roles: The system enforces strict access boundaries across Super Admin, Distributor Admin, Warehouse Manager / Storekeeper, Order Booker, Salesman / Delivery Staff, POS Store Operator, Recovery Staff, and Accountant.   Granular Work-Part Assignments: Within the HRM module, administrators can enable or disable (Accept or Non Accept) specific operational capabilities per employee, including Order Booker, Warehouse Management, POS Store, Normal Invoice, Advance Invoice, and Salesman operations.   Multi-Role & Assignment Flexibility: A single employee can be assigned multiple operational roles and linked to specific warehouses, companies, brands, routes, customer groups, and recovery duties.   Unauthorized Access Protection: Attempting to open a restricted module or route automatically redirects the user back to their authorized workspace accompanied by a clear toast notification.   2.3. Product Master, Multi-Unit Conversion & Batch Inventory EngineProduct Master and Stock Separation: Static catalog definitions (Product Master) and changing inventory quantities (Stock) are maintained as separate system components.   Product Master: Stores SKU Code, Barcode, Product Name, Company, Brand, Category, Sub-Category, Base & Packing Unit definitions, Physical Dimensions (Width, Length, Height, Area, and Volume), and Cloudinary images for both Base and Pack items.   Stock Records: Stores dynamic batch quantities, Warehouse/Zone/Area locations, Purchase rates, Manufacturing (MFG) dates, Expiry (EXP) dates, Total Weight, Stock Condition, and Stock Status.   Multi-Unit Conversion & 3-Tier Pricing: Every product supports a Base Unit (Piece, Bottle, Bar, Packet, Kg, Liter) and Packing Units (Dozen, Box, Carton, Sack, Can) with an explicit conversion ratio (such as 24 Bottles per Carton). Each unit level independently supports three price tiers: Purchase / Trader Price, Wholesale / Sale Price, and Retail / POS End Price.   Batch & Expiry Lifecycle: Every purchase intake generates an independent Batch record with its own MFG date, EXP date, landed cost, weight, and warehouse location so batch updates never corrupt other batches.   Dual Stock Attributes (Condition vs. Status):Stock Condition: Tracks physical state across Normal / Fresh, Damage, Expiry, and Damage + Expiry.   Stock Status: Tracks operational availability across Available, Reserved, Low / Warning (when Available Stock reaches zero or falls below minimum threshold), Out (when Current Stock is zero), Blocked, and Quarantined.   2.4. Pakistan-Style Warehouse Hierarchy & Stock Movement Workflows3-Level Physical Storage Hierarchy: Warehouses follow the structure Warehouse (Main Plot / Shop) → Zone / Section (Normal, Mix, Temperature, Cold Store) → Area / Floor / Rack Location (Floor, Rack, Walked) with area and volume capacity tracking and per-product minimum/maximum quantity limits.   Zero-Quantity Deletion Guard: No warehouse zone or floor/rack area can be deleted while it contains stock; the system enforces a mandatory stock movement to reduce the location's product quantity to zero before unlocking deletion.   Structured Stock Movements: The system records and tracks all stock movements with date, time, preparing user, assigned user, batch, unit, weight, and source/destination:   Inter-Warehouse Transfer: Request, Approval, Dispatch, Receiving, Quantity Verification, Shortage Recording, Damage Recording, and Completion between two warehouses.   Same-Warehouse Transfer: Internal stock movement between zones and floor/rack areas within the same warehouse.   Stock Adjustment & Physical Count: Reconciles Previous ERP Stock against Physical Count (breaking down Normal, Missing, and Damaged units), records the difference, and updates stock upon approval.   Purchase Intake & Put-Away: Receives supplier goods, generates batches, and assigns floor/rack put-away locations.   Expiry & Damage Return to Company: Consolidates damaged and expired batches from quarantine zones for return to the manufacturer/supplier.   Stock Reservation Engine: Approving an order automatically moves the ordered quantity from Available Stock to Reserved Stock. Cancelling an order releases the reservation, while partial deliveries deduct only the delivered quantity and keep undelivered quantities reserved until resolved.   2.5. CRM, 7-Level Location Hierarchy & Beat Planning7-Level Customer Location Structure: Customer addresses follow City → Town/Zone → Area → Route → Street → Pehchan (Local Landmark / Address Remarks) → Customer Shop, supported by Google Maps links, GPS coordinates, and Cloudinary shop photos.   Customer Master & Multi-Shop Ownership: Supports Wholesalers, Retailers, and Sub-Distributors with multiple contact persons, multiple bank/mobile wallet accounts (Bank, EasyPaisa, JazzCash), credit limits, payment conditions (Paid/Cash, Credit Allowed, Advance), tax/discount/scheme group links, and customer ID card printing. A single owner operating multiple shop locations maintains separate transaction histories per shop.   Territory & Beat Plan Management: Administrators configure territories (Brand Wise, Warehouse Wise, District Wise, or Booker Wise) and build day-wise Beat Plans (Monday to Sunday) by connecting Areas, Routes, and accepted Customers, with 1-click Beat duplication for multi-booker assignments.   2.6. Two-Level Invoice Calculation Engine, Rules & Order OperationsOrder Sources & Approval Control: Accepts orders from the Booker Mobile Portal, Customer Phone, WhatsApp, Online Marketplace, POS Counter, and Direct Distributor Office Visits. Every booked order remains in pending state until approved by an authorized administrator or operator.   Two-Level Commercial Calculation Engine:Level 1 (Item Level): Calculates line-item Product Rate, Unit Conversion, Weight (KG), Item Discounts (Flat General, Percentage, or reverse discount calculation from a target custom Sale Rate), Item Charges (by Rate, Quantity, or Weight), Item Taxes (GST %), and Product-Level Free Schemes (Same-Product or Cross-Product free units inserted at zero price with tracked weight).   Level 2 (Grand Invoice Level): Aggregates Total Items, Total Quantity, Total Weight (KG), Total Volume (Cubic Feet), and Gross Amount, then applies Grand-Level Discounts (Amount-based or Weight-based in General+Auto, Slab, or Percentage mode), Grand-Level Charges, Grand-Level Target Schemes, and Invoice Notes to produce the final Net Payable Amount.   Delivery Planning & Operational Sheets: Selecting approved orders and pending credit recoveries calculates total load value, weight, and volume, and generates four synchronized operational documents and employee tasks: Customer Bills, Warehouse Dispatch Sheet, Salesman Delivery Sheet, and Recovery Sheet.   2.7. Pending Tasks, Field Portals (Booker, Salesman, POS) & RecoveryTask-Based Execution & Closing: Every operational duty (Delivery Dispatch, Payment Recovery, Return Put-Away, Warehouse Transfer, Normal-to-Expiry Quarantine, Purchase Put-Away, and Physical Stock Count) is tracked in the Pending Task queue (Fresh, Draft, Pending, Complete) with mandatory task-wise closing and automatic task report generation.   Salesman Deal & On-Spot Modification Workflow: During delivery, salesmen can view Original Invoice, Edit Invoice (reduce/cancel item quantities as returns, adjust discounts, pick up extra damaged/expired customer returns, or sell additional items from Extra Dispatch buffer stock), collect payments (Cash, Online via JazzCash/EasyPaisa/Bank, or Cheque with bank and due date), and record trip expenses (Gas/Petrol, Work/Maintenance, Enjoyment/Refreshment).   POS Counter Workflow: Provides rapid Retail and Wholesale billing for walk-in and registered customers with category/brand filters, unit selection, instant invoice printing, and daily sales/profit reporting.   2.8. Double-Entry Financial Accounting, Dashboards, Reports & AutomationSynchronized Financial Accounting: Every approved sale, purchase, return, recovery, adjustment, and expense automatically posts to the accounting engine, maintaining Trial Balance, Income Statement / Profit & Loss, Balance Sheet, Cash Flow Statement, General Ledger, Journal Entries, Accounts Receivable (Customer Ledger), Accounts Payable (Supplier Ledger), Bank Reconciliation, and Day Book with full audit trails.   10 Dedicated Dashboards & 19+ Business Reports: Provides role-permissioned dashboards for Main Business, Inventory, Purchase, Sales, Accounts, CRM, Supplier, Employee/Task, POS, and Reports, alongside 19+ transaction-linked business reports supporting PDF, Excel, CSV, Print, and restricted Company-Wise Information Sharing.   Automated Notifications & Rules Engine: Continuously monitors and triggers alerts for Low Stock, Expiry windows, Pending Order Approvals, Customer Credit/Payment Dues, Supplier Dues, Task Deadlines, and Invoice Modifications/Cancellations, while automatically drafting purchase requirements when stock falls below minimum thresholds without creating duplicate transactions.   3. Non-Functional Requirements (NFRs)3.1. Performance, Scalability & Zero-Scroll Viewport ErgonomicsHeavy-Load Resilience & Server-Side Pagination: All listings, ledgers, and stock tables use indexed MongoDB queries and server-side pagination so page response times remain under 1.5 seconds even when the database scales to hundreds of thousands of invoices and stock movements.   Zero-Scroll Viewport Design: Desktop screens (>= 1024px) are engineered around a fixed viewport app shell where KPI cards, compact filter toolbars, and paginated tables fit cleanly on screen without requiring unnecessary vertical page scrolling, scrolling only inside bounded data containers when required.Mobile-First Responsive Adaptation: Every screen adapts seamlessly from 320px mobile devices to 1920px+ widescreen monitors using Tailwind CSS, converting multi-column desktop tables into clean, touch-friendly stacked cards on mobile viewports (< 768px).   3.2. Visual Theme, Usability & Anti-Slop QualityStrict Blue & White / Blue & Black Theme: Light mode uses crisp white and cool slate surfaces with royal/ocean blue accents; dark mode uses deep black/obsidian surfaces with vibrant electric/cyan blue accents. Theme switching applies smooth CSS transitions across all components, modals, and charts. Purple hues and AI-generated visual slop are strictly forbidden.   Beginner-Friendly Operational Flow: Navigation, forms, and task wizards use clear, everyday terminology and step-by-step automated flows so any operator can understand and execute tasks immediately without technical training.   3.3. Security, Reliability & AuditabilityAuthentication & Encryption: Passwords are encrypted using bcryptjs, API sessions are secured via short-lived JWT access tokens and HTTP-only refresh tokens, and all inputs are sanitized against NoSQL injection and XSS attacks.   Transactional Integrity & Audit Trail: Critical stock and accounting mutations run inside atomic database transactions and record before/after states in an immutable audit log.   Graceful Error & 404 Handling: Unrecognized routes render a custom theme-aware 404 Page, and network or validation errors display inside clean global modals or toast notifications rather than raw crash screens.   4.
